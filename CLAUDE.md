## Current state: Clap to Destroy lobby
The base (player, physics, sky, material/texture helpers) now runs **Clap to Destroy**: a lego-studded lobby recreated from the owner's reference screenshots, a HUD, synthesized sfx, server-side saves and the clap loop (click/CLAP to gain SKILL and clap beach props apart for Wins; gauntlets unlock by Wins; rebirth; training pools; timed free reward; hidden pumpkins for the level bar). 5X SKILL (40M Wins) and 2x WINS (400K Wins) are permanent one-time Wins purchases. Paid HUD buttons (Shop, Starter Pack, Quests) only toast "coming soon"; AUTO CLAP costs 1K Wins once, then toggles on/off. **Economy pacing** (config.js "Economy pacing" comment): tuned with a playthrough sim so an efficient player needs ~2h20m (never under ~2h) to hold `WORLD2_SKILL` (100M), with fast unlocks in the first ~10 min. The beach is 1 km (`LOBBY.beach`), prop Wins grow x1.65 per 100 m (`DESTROYABLES.zone`), the wave reaches ~880 m at 100M SKILL (`WAVE`), and distance/multiplier signs line the cliffs every 100 m (`landmarks.js` `buildDistanceSigns`, drawn only near the view focus). Retune those numbers together; world signs read prices from config (never hard-code them). The save lives ONLY on the server (no localStorage): `net.js` joins the backend room, which loads/saves the player's Mongo doc, relays other players + their clap effects, runs Daily Rewards and the leaderboards. A guest's or offline progress lasts the page. `GAME_SLUG` is `clap-to-distroy`. The old code is not in the tree; it is in git `HEAD` (`git show HEAD:src/<file>`) apart from uncommitted edits made before the cleanup, so check there before rewriting something generic (windows shell, HUD, net, audio, eggs, pets).

Three.js (vanilla, no React) + Vite + Rapier (`@dimforge/rapier3d-compat`, wasm inlined; `main.js` awaits its init at top level, hence `build.target: 'es2022'`). Everything is procedural (canvas textures); the only imported model is the Bloxity base rig `public/avatars/player.glb`. Font: Fredoka (loaded in `index.html`).

- `npm run dev` / `npm run build`. `VITE_DEV_MODE=true` (see `.env.example`) skips the Bloxity SDK/CDN. Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting (main = prod, dev = dev channel).
- All tunables are in `src/config.js` (the rest of `src/` holds no theme values). It now has: identity (`GAME_SLUG`, `GAME_TITLE`, `DEV_MODE`), the world (`LOBBY`, `WATER`, `SPAWN`, `SPAWN_FACING`), game rules (`CLAP`, `GAUNTLETS`, `DESTROYABLES`, `REBIRTH`, `TRAINING`, `PUMPKINS`, `GIFT`, `SAVE_KEY`), `MODES`, `PHYSICS`, `PLAYER_DIMS`, the look (`RENDER`, `FOG`, `TIME_OF_DAY`, `LIGHT`, `CHARACTER_COLORS`, `MATERIAL_PBR`, `GRAPHICS_PRESETS`, `BLOOM`, `NEON`, `graphicsPreset`), `TOUCH`, `CAMERA`, `SETTINGS`, and the rig (`RIG*`, `PROPORTIONS`, `ANIM`).
- All Bloxity SDK calls go through `src/bloxity.js` and must never throw (SDK may be blocked). It handles init/loading steps, auth (user/guest), settings (`graphics_quality`, `camera_sensitivity`, `show_fps`, `fullscreen`), avatar + proportion change events, the portal `respawn_request` event, the avatar customizer, and the matchmaker helpers the future net layer needs (`resolveServerEndpoint`, `locateRoom`, `updateRoom`).

## Files (`src/`)
- `main.js`: boot order = Bloxity SDK -> renderer -> Rapier -> lighting, fx, lobby (+ colliders), HUD, player body -> avatar (async, swaps in when ready) -> game -> loop (physics, interpolate player, avatar animator, game, camera, lobby, fx, lighting, bloom render). `__game` (dev only) exposes `player`, `scene`, `renderer`, `camera`, `postfx`, `bodies`, `toggleMode`, `lobby`, `game`, `fx`, `teleport(x, y, z, facing)` (facing `Math.PI` = north, -Z).
- **Player**: `player.js` kinematic capsule + Rapier `KinematicCharacterController` (autostep, slopes, snap-to-ground, pushes dynamic bodies), own gravity/jump (coyote time + buffer). Feet position is `player.position`; `player.renderPosition` is interpolated for drawing. Falling below `PHYSICS.killY` respawns. `camera.js` third-person chase cam (boom, wheel zoom, wall clearance via `segmentClear`, speed FOV) and first person at the inner zoom end; `modes.js` `character` (avatar visible) / `player` (first person, avatar hidden), V toggles. `input.js` keyboard / mouse into `inputState`, `onWorldClick` (the clap); `touch.js` + `touch.css` touch controls.
- `avatar/`: `character.js` (player.glb or procedural fallback), `loader.js` (Bloxity cosmetics + proportions from the CDN, `cdn.js`), `rig.js` + `animator.js` (procedural idle/run/airborne/landing; tunables in `ANIM`).
- **Physics**: `physics.js` Rapier world, fixed 60 Hz step with an accumulator; dynamic meshes bound via `bindMesh`/`addDynamic` are interpolated between ticks. Static geometry uses `addFixed` / `addFixedBoxFor`. `segmentClear` is the camera's ray against static colliders only.
- **Lobby** (`lobby/`, layout numbers in `LOBBY` in config; north = -Z): `index.js` `buildLobby(scene, lighting, fx)` places everything and returns the interactive parts (destroyables, showroom, pads, gift, pumpkins). `terrain.js` merged studded plates + colliders (hub floors from `LOBBY.whiteFloors`/`grassFloors`, CLAP ZONE band texture, beach, water channels, terraced cliffs, the tall brown checker hub walls, the waterfall + pool on the south wall), `plaza.js` the south end (leaderboards fed by game.js from `LEADERBOARD_RIVALS` + the local player, pet egg row, golden cat statue, WORLD 2 portal, logo sign), `skyline.js` mountain rings + wisps that follow the player, `props.js` prop builders (palms, block trees, pumpkins, posts, beach props per `DESTROYABLES` kind), `gauntlets.js` glove models per style + showroom plinths + Royal Phoenix, `landmarks.js` Admin Egg, lucky block, BEACH signs, FREE REWARD, `lanes.js` the east training lanes (`LOBBY.lanes`; fenced off with invisible walls, the player trains by standing on the plaque at the entrance: auto-clap every `TRAINING.cooldown` s + a shockwave running down the lane: themed scrolling treadmills sand/ice/wood/crystal/sakura/royal/admin with fences, entrance plaques, end gates, cube trees, petal/neon/gold particles), `labels.js` `Billboard` (multi-line redrawable text sprites + icons), `kit.js` world-UV plates, cached materials, `Batcher`, `fonts.js` (Fredoka + Luckiest Guy readiness).
- **Game**: `game.js` rules + save (`SAVE_KEY`), `hud.js`/`hud.css` DOM HUD (z-index above the touch zones; `--u` design unit = 1px at 1920x990; short/portrait/touch layouts via media queries; `setReservedTop` from `bloxity.onReservedAreas`), `fx.js` pooled particles (soft glow, sparkles, shards), instanced debris, number popups, ground rings, `audio.js` Web Audio sfx. Rules tunables: `CLAP`, `GAUNTLETS`, `DESTROYABLES`, `REBIRTH`, `TRAINING`, `PUMPKINS`, `GIFT`; clap pose `ANIM.clap` (layered over arms in `animator.js`).
- **Saving** (`net.js` + game.js): `game.snapshot()` is the whole state; game.js pushes it through `onSave` (3 s after a change, on tab hide and unload) and net.js sends `saveProgress` only when it changed, only once the server answered for this identity (`net.canSave`) and never for guests. On join the server answers `progress` (a doc: `game.hydrate` replaces the state; after a reconnect the newer local state is kept and pushed instead), `noProgress` (new account: keep the state and save it) or `serverError` (saving stays off so a doc that could not be read is never overwritten). main.js holds the first frame until `net.loaded` (max ~5 s). Daily Rewards are the server's 7-day UTC calendar (`daily` / `dailyResult`; a reward is granted only on `ok`); the plaza boards Level / Time / Wins come from the server's `leaderboard` (Wins may also come from the Bloxity SDK boards in `pullRealBoards`; Robux Spent stays empty). Old localStorage keys are removed on boot.
- **Multiplayer** (config `NET`, `SERVER_URL` = `VITE_SERVER_URL`, else the Bloxity SDK resolves the server; none = offline): `net.js` joins room `world` and sends `pose` (10 Hz, only on change), `loadout` (gauntlet / trail / pets, polled every 0.5 s from `game.loadout()`), `setAvatar` (Bloxity look JSON) and `fx` (game.js `onFx`: `clap`, `wave` with its range, `train`). `remotePlayers.js` draws the roster: nearest `NET.maxRemotes` players only, each the base rig wearing their Bloxity skin / parts / hats (loader.js caches accessory meshes + textures), the same procedural animator driven by relayed speed + grounded (clap layered on `fx`), name tag (Billboard), up to `NET.petsMax` pets (`pets.js` followers) for the nearest `NET.petRemotes` players, shadows / tags / pets / animation only inside their `NET.*Range`. Their clap bursts + rings use the shared `fx` pools; `remoteFx.js` runs their shockwave (shaders exported from `wave.js`, pooled slots built on first use, tinted by their trail, light crest dust only near the viewer). Remote waves are visual only: the beach props are each player's own. No sound for remote claps. Dev: the `dev-remote` launch config (port 5231, server ws://localhost:2567).
- **Windows** (ported from Wave Height Surf's `ui.js`, sized from the owner's screenshots; `--u` = 1px at 1920x990 like the HUD): `ui.js` the shell (frame, title over the top edge, corner icon, red X; one open at a time; Esc / backdrop closes; `closeTopWindow` runs before Bloxity's menu on Esc), `windows.js` + `windows.css` the views, opened by the HUD buttons: Rebirth (Before/After +Nx SKILL, rebirth level bar 1..`REBIRTH.level` on a log scale of SKILL, Level N / Rebirth, Skip Rebirth for Wins, Auto Rebirth), Inventory with Gauntlets / Pets ("My Pets": detail card, lock, INDEX, Auto Delete, trash, Equip Best, sort) / Eggs / Boosts tabs, Trails (tint the clap wave via `wave.setColor`, x Wins), Playtime Rewards (session clock; the Gifts tile shows the next one) and Daily Rewards (calendar button, 24 h, streak breaks after 48 h). `icons.js` window SVGs (+ `public/ui/rebirth.png`), `pets.js` cube-pet portraits, 3D followers and the hatch overlay. Tunables: `PET_KINDS`, `EGGS` (plaza stands by key: walk up + E to hatch; reward eggs wait in the Inventory), `PETS`, `BOOSTS`, `TRAILS`, `PLAYTIME`, `DAILY`, `REWARD_GAUNTLETS`. The SKILL multiplier = (1 + rebirths) x equipped pets' mults (summed) x the SKILL boost; Wins x trail boost x the Wins boost.
- **Clap wave** (Bowling Roll's Run Lane, as a shockwave): `wave.js`. Standing in the Clap Zone band (`LOBBY.band`) shows the green CLAP over the SKILL bar (`hud.setClapZone`; F on keyboard; game.js `clapZone`). Phases windup (camera swings round to face the player, clap) -> wave (a ring of light runs north down the beach, range from SKILL per `WAVE`, every prop it reaches breaks via game.js `hits`, distance counter `.wave-distance`) -> hold -> return (camera back behind the player) -> pay (the Wins total as one "+N" trophy pop `.wave-reward`). `player.frozen` and `hud.setCinematic` (HUD + touch controls hidden) last the whole sequence; `game.focus()` / `game.applyCamera()` hand main.js the wave's lighting focus and camera. Shots blend by position + yaw/pitch (`blendPose`) so a half turn orbits round the player. Normal clicks/the touch CLAP still clap for SKILL (blocked while the wave runs).
  - **The beach is closed to players**: `wave.js` puts an invisible wall along the band's north edge (`WAVE.gate`; collision group `INVISIBLE_WALL` from physics.js, which the camera ray `segmentClear` ignores so the boom never pulls in against it) with a cyan force-field film that fades in within `showWithin` m. Hidden pumpkins on the beach are collected by the wave as it passes them.
  - **Destruction feel**: each prop the wave reaches goes through game.js `breakUp`: an impact `fx.blast` (chunky long-lived debris thrown along the wave, confetti, dust, sparkles), then small props are launched spinning out to the sides and burst on landing, big ones (`WAVE.crumbleSize`) squash and crumble in place. `wave.smashed(size)` drives the combo counter (`.wave-combo`: "Nx SMASH!" + running Wins), the rising pentatonic combo chime (`sfx.smash(size, step)`), camera shake, and hit-stop on big props (`WAVE.hitStop`). The crest kicks up sand at `WAVE.dustRate`/s, speed lines (`.wave-lines`) and `sfx.rumble` follow the wave's speed, the reward counts up with `sfx.tick` and a confetti burst. `audio.js` runs everything through a compressor so stacked smashes punch instead of clipping. Per-prop "+N" popups are skipped for wave hits (the chase camera flies through them); particles fade within ~5 m of the camera (fx.js vertex shader) so driving through dust never whites out the screen.
- **Sky and light**: `lighting.js` sky shader, stars, PMREM environment, shadowed sun following the player, fog, day/night blend (N). `addLamp` lights six hub pumpkin posts at night; `setMoods(sky)` is unused. Moods take `sunDisc` (0 hides the sun in the sky) and `fogColor`. `postfx.js` bloom (EffectComposer: HDR half-float render -> UnrealBloomPass -> OutputPass), on for the High/Ultra presets only (`BLOOM`; threshold 2.0 so sunlit surfaces never bloom).
- **Materials and textures**: `textures.js` canvas painters (cracked sand, water ripples, grass/tiles/crates/planks, outlined text, soft dots, sparkles, ...) and `toTexture` / `mulberry32`. `propkit.js` shared prop helpers: `std`, `glow`, `neon(color, k)` (unlit, HDR-bright with bloom; switched by `setNeonBloom`), `put`, `solidBox` / `solidPole` colliders, `label` (outlined text sprite, repainted once Fredoka loads). `bake.js` `bake` / `bakeInPlace` merge static meshes, folding plain-coloured standard materials into vertex colours so a prop draws in 1-3 calls (mark animated subtrees or per-instance materials `userData.live`).
- Controls: WASD/arrows, Shift sprint, Space jump, left click on the world = clap + grabs the cursor for mouse look (pointer lock; Esc releases it; drag-look where lock is refused), right-drag look, E = the proximity prompt's action (tap the prompt on touch; game.js `actions`), Esc opens the portal menu, wheel zoom, V mode, N day/night, R respawn; touch has a CLAP button. Never bind P (CrazyGames: Boxity's pause menu).
- Graphics: `graphicsPreset(name)` in config resolves the preset; on coarse pointers the default is Medium and every preset is capped by `MOBILE_GRAPHICS_CAP` (DPR 1.5, 1024 shadow map, no bloom), because the Bloxity SDK sends `High` itself.
- Boxity layout (required to publish, docs.bloxity.io Platform UI rules): Boxity draws the menu / pause menu, chat, emotes, avatar editor, invite, leaderboard and sign-in itself in a toolbar in the top-left corner with the chat feed under it, so the game never draws those buttons and keeps any HUD out of those rectangles (`bloxity.onReservedAreas`).
